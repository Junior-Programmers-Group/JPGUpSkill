The Anatomy of a Website

Think of a website like building a house:
HTML is the structure (walls, doors), CSS is the interior design (paint, furniture), and JavaScript is the electricity (making things work). Today, we focus on the house and the paint!

HTML <Building Block>

HyperText Markup Language

  • Defines the structure.
  • Tells the browser what is a title, what is an image, and what is a link.
  • "This is a button."

CSS <The Aesthetic>

Cascading Style Sheets

  • Defines the visual look.
  • Controls colors, spacing, and layout (side-by-side vs top-to-bottom).
  • "Make the button red and rounded."

HTML 101: Tags & Elements

HTML uses tags wrapped in angle brackets < > to wrap around content and give it meaning.

1. Opening & Closing Tags

Most tags come in pairs. The closing tag has a forward slash /.

<h1>Welcome to my Portfolio!</h1>
<p>My name is Ethan.</p>
  • h1 = Heading 1 (Biggest text)
  • p = Paragraph (Normal text)

2. Self-Closing Tags

Some tags don't wrap text, they just insert something (like an image). They don't need a closing tag.

<img src="profile.jpg" alt="My Photo">
<br> <!-- Line break -->

Structuring a Web Page

We used to put everything in a generic box called a <div>. Now, we use Semantic HTML, which means giving boxes clear names so Google and screen readers know what they are.

The HTML5 Page Layout

<body>
  <header>
    <nav> Home | About </nav>
  </header>

  <main>
    <section id="about">
      <h2>About Me</h2>
      <p>I am a developer.</p>
    </section>
  </main>

  <footer> © 2026 </footer>
</body>

Tag Definitions

  • <header>: The top bar of your site.
  • <nav>: Navigation links.
  • <section>: A specific topic area (e.g., "About Me", "My Projects").
  • <footer>: The bottom of the page.
  • <div>: A generic grouping box (still useful for styling!).

The Document Object Model makes your webpage interactive!

  • Tree Structure: Browser converts HTML into a tree of object nodes.
  • JavaScript Bridge: JS can select, read, modify, or delete any node live.
  • Events: Listen for clicks, keypresses, or form submissions.

Where does CSS go?

You have two main ways to tell your HTML about your CSS styles.

1. The <style> Tag

Written directly inside the HTML file's <head>. Good for very small, quick tests.

<head>
  <style>
    h1 { color: red; }
  </style>
</head>

2. The <link> Tag (Best Practice)

Links to a separate .css file. This is the industry standard because it keeps your code clean and organized.

<head>
  <link rel="stylesheet" href="styles.css">
</head>

CSS Basics: Colors & Variables

Color vs. Background

Don't mix these up!

  • color: Changes the color of the text itself.
  • background-color: Changes the color of the box behind the text.
.error-message {
  color: white;
  background-color: darkred;
}

CSS Variables (Tokens)

Store colors in one place so you don't have to memorize hex codes!

:root {
  --my-red: #ff2a4b;
}

.button {
  background-color: var(--my-red);
}

CSS Box Model: Margin

Outside Spacing

Margin creates space outside the element's border, pushing neighboring boxes away.

  • Individual sides: margin-top, margin-right, etc.
  • Shorthand: margin: 20px; (All sides equal).
  • 2-Value Shorthand: margin: 10px 20px; (Top/Bottom, Left/Right).
Margin Space (Pushes Away)
Element Border & Content
.card {
        /* Push other elements away */
        margin: 24px;
      }

Centering & Margin Collapse

Key margin tricks and behaviors every developer should know.

  • Horizontal Centering: margin: 0 auto; centers block elements with a fixed width.
  • Margin Collapse: Vertical margins of adjacent elements combine into a single margin.
margin: 0 auto;
◄ Auto Space ► ◄ Auto Space ► 
.container {
        width: 800px;
        /* Center horizontally */
        margin-left: auto;
        margin-right: auto;
      }

CSS Box Model: Padding

Inside Spacing

Padding creates breathing room inside the element, between content and border.

  • Individual sides: padding-top, padding-left, etc.
  • Background inclusion: Padding takes on the background color/image of the box.
  • Shorthand: padding: 12px 24px; (Vertical, Horizontal).
Padding (Space Inside Border)
Content Area
.button {
        background-color: var(--my-red);
        color: white;
        padding: 12px 24px;
      }

Box Sizing (box-sizing)

Prevent padding from growing your elements unexpectedly!

  • content-box (Default): Padding is added to width, making the element bigger.
  • border-box (Recommended): Padding is included inside the specified width.
content-box
Width + Padding
border-box
Fixed Width
*, *::before, *::after {
        /* Universal reset for predictable sizing */
        box-sizing: border-box;
      }

Naming Things: Tag, Class & ID

How do we tell CSS exactly which part of the HTML to paint red? We use Selectors. Think of an ID as a Passport Number (unique), a Class as a Uniform (groups of people), and a Tag as "Human" (everyone).

1. Tag Selector

Targets EVERY paragraph on the page.

p {
  color: white;
}

HTML: <p>

2. Class Selector (.)

Targets any element wearing the .btn uniform.

.btn {
  background: red;
}

HTML: <button class="btn">

3. ID Selector (#)

Targets one UNIQUE element on the page.

#navbar {
  height: 60px;
}

HTML: <nav id="navbar">

CSS Layouts: Flexbox (The 1D Line)

Flex Basics & Navbar

Arrange items side-by-side effortlessly along a 1D line.

  • display: flex; Enables the flexbox layout context.
  • justify-content: Aligns items along the main axis.
  • align-items: Aligns items along the cross axis.
.navbar {
        display: flex;
        justify-content: space-between;
        align-items: center;
      }

Changing Axis (flex-direction)

The main axis direction dictates how layout properties behave!

  • row (default): Main axis = Horizontal, Cross axis = Vertical.
  • column: Main axis = Vertical, Cross axis = Horizontal.
.sidebar {
        display: flex;
        flex-direction: column; /* Flips Main Axis to vertical */
        justify-content: space-between;
      }

Flexbox: Main Axis (justify-content)

justify-content controls how items are distributed along the main axis (horizontally by default in row layout).
  • flex-start (Default) Items align to the start.
  • center Items group at the center.
  • flex-end Items align to the end.
  • space-between Equal space between items.
  • space-around Equal space around each item.
  • space-evenly Equal space between all items and edges.

Flexbox: Cross Axis (align-items)

align-items controls how items align along the cross axis (vertically by default in row layout).

CSS Layouts: Grid (The 2D Checkerboard)

While Flexbox is great for a single row, CSS Grid is perfect for arranging things in rows AND columns at the same time. Think of a photo gallery or a set of project cards. 
.project-gallery {
  display: grid;
  /* Make columns automatically fit! */
  grid-template-columns: repeat(
    auto-fit,
    minmax(200px, 1fr)
  );
  gap: 1rem; /* Space between cards */
}

The auto-fit magic trick means you don't even need to write separate code for mobile phones. The browser will automatically wrap the cards when the screen gets too small!

Bringing it to Life: Hover & Transforms

We can make elements react when a user points their mouse at them using the :hover state and transform property.

The Code

.card {
  transition: transform 0.3s ease;
}

/* When the mouse hovers over it... */
.card:hover {
  transform: translateY(-10px) scale(1.05);
}

What it does

  • transition: Makes the movement smooth (takes 0.3 seconds) instead of snapping instantly.
  • translateY(-10px): Moves the card UP by 10 pixels.
  • scale(1.05): Makes the card 5% bigger.

Mobile-Friendly: Media Queries

A layout that looks great on a laptop might look terrible on a phone. Media Queries act like an "If statement" for your CSS based on screen size.

"If the screen is smaller than 600px wide, change the navbar from a row into a stacked column."

/* Desktop Default */
.navbar {
  display: flex;
  flex-direction: row;
}

/* Mobile Rule */
@media (max-width: 600px) {
  .navbar {
    flex-direction: column;
  }
}
  • Always build your HTML for phones first, then add complexity for larger screens.
  • Use the browser's Inspect Element / Developer Tools to simulate a phone screen while you code!
